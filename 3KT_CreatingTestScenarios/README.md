# Создание тестовых сценариев

## Вариант 1. Интернет-магазин
В системе три модуля: поиск товаров, корзина и оформление заказа.

### Сценарий 1. Найти товар и добавить его в корзину
Предусловия: пользователь вошёл в систему, корзина пустая.

Шаги:
1. Найти товары в категории «Электроника» с ценой до 5000 ₽.
2. Выбрать товар из списка.
3. Добавить его в корзину, количество 2 шт.

Ожидаемый результат:
- в поиске только товары из «Электроники» дешевле 5000 ₽, список отсортирован;
- в корзине лежит выбранный товар, 2 шт.;
- сумма в корзине посчитана правильно, с налогом.

### Сценарий 2. Изменить корзину
Предусловия: в корзине два товара, на один есть скидка.

Шаги:
1. Поменять количество первого товара на 3.
2. Удалить второй товар.
3. Перейти к оформлению заказа.

Ожидаемый результат:
- после каждого действия сумма пересчитывается с налогом и скидкой;
- на странице оформления те же товары и та же сумма, что в корзине.

### Сценарий 3. Оформить заказ и оплатить картой
Предусловия: в корзине есть товар, у пользователя указан email.

Шаги:
1. Перейти к оформлению заказа.
2. Ввести правильный адрес доставки.
3. Выбрать оплату картой и ввести правильные данные карты.
4. Подтвердить заказ.

Ожидаемый результат:
- заказ создан;
- на почту пришло письмо с товарами, суммой и адресом;
- корзина очистилась;
- все действия записаны в лог.

### Сценарий 4. Оформить заказ с неправильными данными
Предусловия: в корзине есть товар.

Шаги:
1. Перейти к оформлению заказа.
2. Ввести адрес без индекса.
3. Ввести номер карты неправильной длины.
4. Подтвердить заказ.

Ожидаемый результат:
- заказ не создан, система показывает ошибки;
- товары остались в корзине;
- письмо не пришло;
- попытка записана в лог.

### Сценарий 5. Два пользователя одновременно
Предусловия: два пользователя вошли в систему, у каждого своя корзина.

Шаги:
1. Оба одновременно находят один и тот же товар.
2. Оба добавляют его в корзину.
3. Оба оформляют заказ.

Ожидаемый результат:
- корзины не перепутались;
- создано два разных заказа;
- каждый получил своё письмо;
- в логе действия обоих пользователей записаны отдельно.

## Вариант 2. Система управления задачами

В системе два модуля: управление задачами и отчёты. Ещё есть связь с календарём и история изменений.

### Сценарий 1. Создать задачу

Предусловия: пользователь вошёл в систему, календарь подключён.

Шаги:
1. Создать задачу «Подготовить отчёт» с описанием, дедлайном 15.10.2026 и высоким приоритетом.

Ожидаемый результат:
- задача создана со статусом «в работе»;
- в календаре появилось событие на 15.10.2026;
- в истории изменений есть запись о создании задачи, время и кто создал.

### Сценарий 2. Изменить задачу

Предусловия: есть задача с дедлайном и событием в календаре.

Шаги:
1. Поменять дедлайн на другую дату.
2. Поменять приоритет с высокого на средний.
3. Сохранить.

Ожидаемый результат:
- у задачи новый дедлайн и приоритет;
- событие в календаре перенеслось на новую дату;
- в истории изменений видно, что поменяли, когда и кто.

### Сценарий 3. Удалить задачу

Предусловия: есть задача с событием в календаре.

Шаги:
1. Удалить задачу.
2. Отфильтровать задачи по её статусу и приоритету.

Ожидаемый результат:
- задачи нет в списке после фильтрации;
- событие из календаря удалено;
- удаление записано в историю изменений.

### Сценарий 4. Поменять статусы и получить отчёт

Предусловия: есть 5 задач со статусом «в работе».

Шаги:
1. Перевести 3 задачи в «выполнено» и 1 в «отменено».
2. Отфильтровать задачи по статусу «выполнено».
3. Сформировать отчёт за текущий месяц.

Ожидаемый результат:
- фильтр показывает 3 задачи;
- в отчёте 3 выполненные, 1 отменённая и 1 в работе;
- у выполненных задач указано, сколько времени на них ушло;
- все смены статусов есть в истории изменений.

### Сценарий 5. Выгрузить отчёт

Предусловия: отчёт за период уже сформирован.

Шаги:
1. Выгрузить отчёт в PDF.
2. Выгрузить тот же отчёт в Excel.
3. Открыть оба файла.

Ожидаемый результат:
- оба файла открываются без ошибок;
- цифры в файлах совпадают с отчётом в системе.
