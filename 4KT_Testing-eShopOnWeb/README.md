# КТ-4. Интеграционное тестирование методом «большого взрыва» (eShopOnWeb)

Все модули проекта интегрировались одновременно, за один этап, после чего система тестировалась целиком. Для этого использовались две команды.

Подготовка: в `src/Web/appsettings.json` и `src/PublicApi/appsettings.json` добавлена настройка `"UseOnlyInMemoryDatabase": true`, чтобы приложение работало с базой данных в памяти вместо SQL Server LocalDB.

## Команда 1. Сборка всех модулей одновременно

```
dotnet build eShopOnWeb.sln
```

Что делает: восстанавливает зависимости и собирает за один раз все проекты решения: ApplicationCore, Infrastructure, Web, PublicApi, BlazorAdmin, BlazorShared и четыре тестовых проекта.

Что увидели:
- все модули собраны успешно, ошибок нет;
- итог: «Сборка успешно выполнено с предупреждениями (13)», время 24,9 с;
- NU1903 (ApplicationCore): System.Text.Json 8.0.3 содержит две уязвимости высокого уровня (GHSA-8g4q-xg66-9fp4, GHSA-hh2w-p6rv-4g7w);
- NU1902 (Web): Azure.Identity 1.10.4 содержит две уязвимости среднего уровня (GHSA-m5vv-6r4h-3vj9, GHSA-wvxc-855f-jvrv);
- SYSLIB0051 (ApplicationCore, `Exceptions/EmptyBasketOnCheckoutException.cs`, строка 12): используется устаревший конструктор исключения для сериализации;
- xUnit2013 (UnitTests — 3 места, IntegrationTests — 1 место): размер коллекций проверяется через `Assert.Equal()` вместо `Assert.Empty` / `Assert.Single`.

## Команда 2. Запуск всех тестов одновременно

```
dotnet test eShopOnWeb.sln
```

Что делает: запускает разом все четыре набора тестов: UnitTests, IntegrationTests, FunctionalTests, PublicApiIntegrationTests. Функциональные тесты поднимают приложение целиком и проходят сценарии пользователя: открытие каталога, добавление товара в корзину, изменение количества (в т.ч. до 0), оформление заказа с перенаправлением на вход, вход в систему, изменение данных аккаунта, доступ к «Моим заказам» без авторизации.

Что увидели:
- итог: всего 74, успешно 74, сбоев 0, пропущено 0, длительность 8,5 с;
- предупреждения об уязвимых пакетах повторились (8 предупреждений);
- `Role ... validation failed: DuplicateRoleName` — при каждом новом запуске приложения в тестах база заново заполняется и роли пытаются создаться повторно (6 раз за прогон);
- `Failed to determine the https port for redirect` — в тестовом окружении не определён HTTPS-порт;
- `Basket.IndexModel.OnPost - ModelState is Invalid` — при добавлении товара в корзину модель запроса не прошла валидацию, но обработчик всё равно выполнился и сохранил данные;
- ключи защиты данных записываются в профиль пользователя (`AppData\Local\ASP.NET\DataProtection-Keys`), то есть тесты зависят от окружения машины;
- логи четырёх тестовых проектов выводятся вперемешку, понять, к какому модулю относится сообщение, сложно.
